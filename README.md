# RSI Divergence Bot

Телеграм-бот, который следит за набором активов на нескольких таймфреймах
и присылает два типа сигналов:

- **ALERT #1** — подтверждённый локальный минимум (фрактал) при RSI ≤ `oversold`.
  Точка запоминается как опорная.
- **ALERT #2** — следующий подтверждённый минимум, у которого **цена ниже**,
  а **RSI выше** предыдущего: бычья дивергенция.

Медвежий сценарий (максимумы, RSI ≥ `overbought`) реализован зеркально
и включается флагом `params.bearish_enabled`.

---

## Быстрый старт

### 1. Секреты

```bash
cp .env.example .env
```

Заполните в `.env`:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | нет | чат, который получает алерты без `/start` |
| `TELEGRAM_ALLOWED_USER_IDS` | нет | белый список `user_id` через запятую; пусто = доступ всем |
| `COINAPI_KEY` | только для `coinapi` | ключ CoinAPI |

`.env` в git не коммитится (см. `.gitignore`).

### 2. Активы

Всё, что нужно править для добавления актива, лежит в `config.yaml`:

```yaml
assets:
  - symbol: HYPEUSDT
    provider: binance
    timeframes: [1H, 4H, 1D]
```

`enabled: false` временно выключает актив, не удаляя его из конфига.

### 3. Запуск

**Docker (рекомендуется):**

```bash
docker compose up -d --build
docker compose logs -f
```

**Локально:**

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.main
```

Нужен Python 3.11+.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | подписаться на алерты |
| `/help` | справка |
| `/list` | активы и их таймфреймы |
| `/add <symbol> <provider> <tf,tf>` | добавить актив, напр. `/add SOLUSDT binance 4H,1D` |
| `/remove <symbol>` | удалить актив |
| `/tf <symbol> <tf> on\|off` | включить/выключить один таймфрейм |
| `/status <symbol>` | текущие опорные точки и последние сигналы |
| `/params` | показать параметры |
| `/params <key> <value>` | изменить параметр на лету |
| `/params reset` | вернуть значения из `config.yaml` |

Правки через `/params` живут в БД и переживают рестарт. Если нужно, чтобы
`config.yaml` всегда побеждал, поставьте `sync.overwrite_params: true`.

## Как это работает

**Планировщик.** На каждую пару (актив × таймфрейм) поднимается своя asyncio-задача.
Она просыпается через `close_delay_seconds` + случайный `jitter_seconds` после
закрытия свечи по UTC. Раз в `reconcile_interval_seconds` набор задач сверяется с БД,
поэтому `/add` и `/remove` подхватываются без перезапуска.

**Детектор работает в режиме replay.** Каждый опрос прогоняет всё окно
(`lookback_bars`) через конечный автомат заново. Это значит, что состояние
восстанавливается само после рестарта или пропущенных опросов — ничего
не теряется. От дублей защищает ключ в SQLite:
`(symbol, timeframe, alert_type, candle_time)`.

**Первый запуск.** Пара помечается `seeded` после первого анализа: исторические
сигналы записываются в БД, но не рассылаются. Дополнительно работает порог
`notify_max_age_bars` — сигнал старше N баров не уходит в чат.

**Задержка подтверждения.** Фрактал требует `fractal_n` баров с каждой стороны,
поэтому сигнал приходит через N закрытых свечей после самого экстремума.
Это плата за отсутствие перерисовки.

**Инвалидация опорной точки** происходит, если RSI ушёл выше `reset_rsi`
(для медвежьего — ниже `reset_rsi_bear`) или если между точками накопилось
больше `max_bars_between` баров.

## Таймфреймы и ресемплинг

Если у провайдера нет нужного таймфрейма нативно, он собирается из младшего.
Выбирается **самый крупный** нативный TF, который делит целевой без остатка:

- Binance `3H` → собирается из `1H`
- CoinAPI `1W` → собирается из `1D` (нативный weekly не используется:
  выравнивание по понедельнику у провайдера не гарантировано)

Агрегация: `open` = первый, `high` = max, `low` = min, `close` = последний,
`volume` = сумма. Незакрытая хвостовая корзина отбрасывается по проверке покрытия,
так что в анализ не попадает частичная свеча.

## Проверка символов CoinAPI

Это единственный шаг, который **обязательно** нужно сделать вручную перед
включением токенизированных акций.

У CoinAPI `symbol_id` — это **не тикер**, а строка вида
`EXCHANGE_SPOT_BASE_QUOTE`. Поэтому в конфиге есть карта:

```yaml
providers:
  coinapi:
    symbol_map:
      AAPLX: BINANCE_SPOT_AAPLX_USDT   # ← пример, проверьте
```

Проверить фактическое имя:

```bash
curl -H "X-CoinAPI-Key: $COINAPI_KEY" \
  "https://rest.coinapi.io/v1/symbols?filter_symbol_id=AAPLX"
```

Возьмите `symbol_id` из ответа и подставьте в `symbol_map`, затем снимите
`enabled: false` с актива. Поставьте `strict_symbols: true`, если хотите,
чтобы бот падал на старте при отсутствии записи в карте, а не пытался угадать.

Оговорюсь честно: доступность токенизированных акций зависит от вашего тарифа
CoinAPI — на бесплатном плане их может не быть вовсе. Лимит запросов там тоже
жёсткий, отсюда `requests_per_minute: 20` по умолчанию.

## Добавление нового провайдера данных

`app/data/template_provider.py` — готовая заготовка. Нужно реализовать один
метод, возвращающий OHLCV-датафрейм, и объявить нативные таймфреймы;
ресемплинг, кэш, троттлинг и ретраи наследуются из базового класса.
Затем зарегистрируйте класс в `app/data/registry.py`.

## Структура

```
app/
  main.py            точка входа, синхронизация YAML → SQLite
  config.py          pydantic-модели конфига и секретов
  service.py         оркестратор: свечи → анализ → дедуп → отправка
  core/timeframes.py таймфреймы и границы свечей в UTC
  data/              провайдеры, HTTP-слой, кэш, ресемплинг
  analysis/          RSI, фракталы, автомат дивергенций
  bot/               хранилище, планировщик, хендлеры, рассылка
tests/               синтетические ряды и сценарии
```

Состояние хранится в `data/state.db`, логи — в `logs/bot.log`
(ротация 5 МБ × 5 файлов) и в stdout.
